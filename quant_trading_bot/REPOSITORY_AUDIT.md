# Initial repository and environment audit

Audit began 2026-11-06 before implementation. The clean existing worktree was on `research/codex-eth-bnb`, with its git metadata pointing at the separate original Stock Predictor repository. No AGENTS.md files were found in this workspace. New files were isolated under `quant_trading_bot/`; no original tracked source, model, dataset, account configuration or experiment was changed.

The repository contains a Flask stock API, SQLAlchemy migrations, legacy equity classifiers/pickles, a large ETH/BNB backtesting library, and `research/codex_eth_bnb` validation, execution, fitted-model, paper, price-action and formations experiments. Existing reports contain already-selected crypto results and holdout manifests; they were not reused as fresh futures evidence. Existing raw datasets found were ETH/BNB/BTC five-minute Parquet and crypto funding, plus an empty SQLite database. No licensed MES/MNQ contract history was found.

Reviewed reusable designs included `backtesting/indicators.py`, `backtesting/engine.py`, and `research/codex_eth_bnb/{analytics,execution,paper}.py`. Indicators and causal execution/uncertainty conventions informed the new implementation. Crypto quantity/funding/liquidation and calendar assumptions were incompatible with CME micro-futures accounting, so the new engine uses verified multipliers, integer contracts and session attribution. Existing APIs and pickle artifacts were not imported into the futures runtime.

Windows 11, Python 3.13.5, and NVIDIA RTX 4090 hardware were detected. Installed PyTorch is CPU-only (`torch.cuda.is_available() == false`). Several Python/node/WSL processes existed; none was stopped, reprioritized or reused. Experiments run one CPU job with fixed seeds. CIM hardware/process queries were initially denied under the original sandbox; after the user resumed with full access the read-only audit completed.

The system volume was almost full. A complete optional install failed with `No space left on device`. A local venv reusing installed packages allowed core work plus small LightGBM/Gymnasium/RL dependencies. No unrelated files or caches were deleted to recover space. `reports/environment.json` records package availability, free disk, processes and source identity; it is regenerated after final verification. The test runner uses project-local temporary directories because the default pytest temp path was initially inaccessible.

Later in the session additional disk space became available without deleting unrelated user files. XGBoost, Optuna, DuckDB and Plotly then installed, and a clean `.clean-check` environment installed the locked dependency set, the editable project and passed `pip check`. The shared development environment's unrelated sentence-transformers/tokenizers versus huggingface-hub conflicts were left untouched. Clean-environment core tests and full-environment advanced tests are recorded separately.
